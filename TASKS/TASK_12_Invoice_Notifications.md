# TASK 12: Invoice and Payment Notifications

## Purpose

Automated email notifications for invoice lifecycle events: invoice sent, payment received, overdue reminders, payout confirmations. Ensures both operators and clients stay informed.

## Priority

High. Critical for user engagement and payment collection.

## Dependencies

- TASK_09: Invoice CRUD.
- TASK_10: Payment Processing.
- TASK_11: Payout Disbursement.
- Email service configured (Postmark, SendGrid, AWS SES).
- Email template engine (Handlebars, Pug, or similar).

## Acceptance Criteria

1. Email sent to Site Owner when invoice sent (with PDF attachment and payment link).
2. Email sent to Site Owner and Operator when payment succeeds (receipt and confirmation).
3. Overdue reminders sent to Site Owner at intervals (Day 1, 7, 14 after due date).
4. Email sent to Operator when payout arrives.
5. Email sent to Operator if payout fails (with instructions to fix).
6. Email sent to Operator when account verification complete (payouts enabled).
7. All emails mobile-responsive with clear call-to-action buttons.
8. Unsubscribe link included (except critical transactional emails).
9. Email delivery tracked (sent, delivered, bounced, opened).
10. Operators can disable overdue reminders per invoice.

## UI Description

No direct UI for sending emails (automated). Configuration UI in settings.

### Email Notification Settings (Operator)

**Location:** /settings/notifications

**Components:**
- Toggle switches for notification types:
  - Invoice sent confirmation (to operator).
  - Payment received confirmation (to operator).
  - Payout confirmation (to operator).
  - Overdue reminders (to clients, enabled by default).
- Global unsubscribe option: "Pause all email notifications for 30 days" (emergency brake).

### Email Notification Settings (Site Owner)

**Components:**
- Toggle switches:
  - Invoice received notifications.
  - Payment receipt emails.
- Email frequency: Immediate (default) or Daily digest.

## API Endpoints (Internal)

### POST /api/v1/notifications/send (Internal API)

**Request Body:**
```
{
  "type": "InvoiceSent",
  "recipient_user_id": "uuid",
  "data": {
    "invoice_id": "uuid",
    "invoice_number": "OP-2025-0001",
    "operator_name": "Drone Pros LLC",
    "client_name": "ABC Construction",
    "amount": 2387.00,
    "due_date": "2025-02-14",
    "invoice_url": "https://...",
    "pdf_url": "https://..."
  }
}
```

**Behavior:**
- Validate notification type and recipient.
- Fetch email template.
- Render template with data.
- Send email via email service (Postmark, SendGrid).
- Create Notification record (status: Pending).
- Update status to Sent or Failed based on email service response.

### GET /api/v1/notifications

**Query Parameters:**
- user_id: UUID (optional, defaults to current user).
- type: InvoiceSent | PaymentConfirmation | etc. (optional).
- status: Pending | Sent | Failed | Bounced (optional).
- limit: Max 100, default 50.

**Response (200 OK):**
```
{
  "notifications": [
    {
      "notification_id": "uuid",
      "type": "InvoiceSent",
      "recipient_user_id": "uuid",
      "subject": "New invoice from Drone Pros: OP-2025-0001",
      "status": "Sent",
      "sent_at": "2025-01-15T14:00:00Z"
    }
  ],
  "total": 23
}
```

**Purpose:** Audit trail, troubleshooting delivery issues.

## Background Jobs

### Job 1: Send Email Notification

**Triggered:** After invoice sent, payment received, payout processed, etc.

**Steps:**
1. Receive notification data (type, recipient, template variables).
2. Fetch user email address and notification preferences.
3. Check if user opted out of this notification type.
4. Render email template.
5. Send email via email service API.
6. Handle attachments (PDF invoice, receipt).
7. Update Notification record with status and sent_at.
8. Log delivery confirmation (message ID from email service).

### Job 2: Overdue Invoice Detection (Cron)

**Schedule:** Daily at 9 AM UTC.

**Steps:**
1. Query invoices where due_date < today AND status = Sent.
2. For each overdue invoice:
   - Check days overdue: (today - due_date).
   - If 1, 7, or 14 days overdue, send reminder.
   - Track reminder count (do not send duplicate).
3. Update invoice status to Overdue (if not already).
4. Log reminder sent.

**Caveats:**
- Do not send reminder if operator disabled for specific invoice.
- Do not send reminder if invoice recently paid (race condition).

### Job 3: Process Email Webhooks (Postmark, SendGrid)

**Triggered:** Webhook from email service.

**Events:**
- **Delivered:** Update Notification status to Delivered.
- **Bounced:** Update status to Bounced, flag user email as invalid.
- **Opened:** Track open event (optional, for analytics).
- **Clicked:** Track link clicks (optional).

**Behavior:**
- Parse webhook payload.
- Find Notification by message ID.
- Update status.
- If bounced, suppress future emails to that address.

## Caveats and Edge Cases

### Email Deliverability

Use reputable email service with high sender reputation. Configure SPF, DKIM, DMARC records. Monitor bounce and complaint rates.

### Large Attachments

If invoice PDF >5 MB (many line items, images), do not attach. Provide download link instead.

### Timezone Handling

Display dates in recipient's timezone. Include timezone indicator (e.g., "Feb 14, 2025 at 5:00 PM PST").

### Overdue Reminder Frequency

After 3 reminders, stop sending automatically. Operator can manually send additional reminders if needed.

### Email Rate Limiting

Email service may rate-limit (e.g., 10 emails/second). Queue emails and throttle send rate.

### Personalization

Use recipient's name in greeting. For Site Owner emails, use organization name if individual name unavailable.

### Link Expiration

Payment links in emails should not expire (allow late payments). Use invoice ID for routing, validate access on page load.

### Email Tracking

Open tracking uses invisible pixel. Some email clients block images, so open rates may be underreported.

### Notification Preferences

Respect user preferences but allow critical transactional emails (payment confirmation, payout failure) to override.

### Duplicate Prevention

Use idempotency key (notification type + invoice ID + reminder count) to prevent duplicate emails if job runs twice.

## Performance Considerations

### Email Sending

Enqueue email jobs in background (do not block API responses). Process queue asynchronously.

### Template Rendering

Cache compiled templates in memory to reduce rendering time (<10ms per email).

### Attachment Generation

If PDF not pre-generated, generate on-demand. Cache PDFs in S3 with 24-hour TTL.

### Bulk Sending

For overdue reminders (potentially hundreds per day), batch send via email service API (send 100 emails in single API call).

## Monitoring and Observability

### Metrics to Track

- Emails sent per day (by type).
- Email delivery rate (%).
- Bounce rate (%).
- Open rate (%) (if tracking enabled).
- Click-through rate (%) on CTA buttons.
- Time from trigger to delivery (p50, p95).

### Alerts

- Bounce rate > 5% (deliverability issue).
- Email sending failures > 2% (email service issue).
- Overdue reminder cron job failed (invoices not tracked).

### Dashboards

- Email volume over time (line chart).
- Delivery status breakdown (pie chart: Sent, Delivered, Bounced, Failed).
- Open and click rates by email type (bar chart).

## Security Checklist

- [ ] Email links include unique tokens (prevent unauthorized access).
- [ ] Unsubscribe links authenticated (prevent abuse).
- [ ] Emails do not contain sensitive data (passwords, full card numbers).
- [ ] Email templates sanitized (prevent XSS if user input included).
- [ ] SPF, DKIM, DMARC configured (prevent spoofing).
- [ ] Rate limiting on email sending (prevent abuse).
- [ ] Bounced email addresses suppressed (GDPR compliance).
